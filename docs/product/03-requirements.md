# 03. Требования к продукту

На текущем этапе функции представлены в виде frontend-прототипа на демонстрационных данных. Описание будущего продукта не означает наличия серверной реализации.


## Назначение документа

Документ содержит требования к поведению системы с точки зрения пользователя.

Каждое требование имеет идентификатор и должно быть проверяемым.

---

## Функциональные требования

### REQ-001. Ввод поискового запроса

Система должна предоставлять пользователю возможность ввести текстовый поисковый запрос на естественном языке.

**Проверка:** пользователь может ввести произвольный текст в поле поиска.

---

### REQ-002. Запуск поиска

Пользователь должен иметь возможность запустить поиск после ввода запроса.

**Проверка:** после ввода непустого запроса пользователь может выполнить поиск.

---

### REQ-003. Обработка пустого запроса

Система не должна запускать поиск, если пользователь не ввёл текст запроса.

**Проверка:** при попытке выполнить поиск с пустым полем система сообщает о необходимости ввести запрос.

---

### REQ-004. Поиск по корпусу документов

Система должна выполнять поиск по заранее сформированному корпусу нормативных и справочных документов финансовой сферы.

**Проверка:** после отправки корректного запроса система возвращает результаты из используемого корпуса документов.

---

### REQ-005. Ранжирование результатов

Найденные документы должны отображаться в порядке их релевантности поисковому запросу.

**Проверка:** результаты поиска представлены в виде упорядоченного списка.

---

### REQ-006. Отображение найденного материала

Для каждого результата поиска система должна отображать информацию, позволяющую пользователю понять содержание найденного материала.

Результат должен содержать:

- название документа или источника;
- релевантный фрагмент текста;
- информацию об источнике.

**Проверка:** каждый отображаемый результат содержит перечисленные данные.

---

### REQ-007. Просмотр источника

Пользователь должен иметь возможность получить более подробную информацию об источнике найденного материала.

**Проверка:** из результата поиска пользователь может перейти к информации об исходном документе или источнике.

---

### REQ-008. Обработка отсутствия результатов

Если по запросу не найдено подходящих документов, система должна сообщить об этом пользователю.

**Проверка:** при отсутствии результатов отображается соответствующее сообщение, а пользователь может изменить запрос и выполнить поиск повторно.

---

### REQ-009. Формирование ответа

В итоговой версии продукта система должна формировать краткий ответ на вопрос пользователя на основе найденных материалов.

**Проверка:** после выполнения поиска пользователь получает сформированный ответ вместе с результатами поиска.

---

### REQ-010. Связь ответа с источниками

Пользователь должен иметь возможность определить, на каких найденных материалах основан сформированный системой ответ.

**Проверка:** вместе с ответом пользователю доступны соответствующие источники.

---

## Требования к взаимодействию

### REQ-011. Основной сценарий на одном пользовательском пути

Пользователь должен иметь возможность пройти основной сценарий без перехода к дополнительным настройкам:

ввод запроса → запуск поиска → просмотр результатов → просмотр источника.

**Проверка:** основной сценарий можно полностью пройти через пользовательский интерфейс.

---

### REQ-012. Повторный поиск

После получения результатов пользователь должен иметь возможность изменить поисковый запрос и выполнить поиск повторно.

**Проверка:** пользователь может отредактировать запрос и получить новый набор результатов без перезапуска приложения.

---

## Границы этапа

Серверная реализация новых функций не входит в текущий этап.


## Требования к расширенному прототипу

| Код | Поведение и проверка |
|---|---|
| UI-013 | Вход и регистрация переключаются в modal; обязательные поля и email проверяются браузером, пароли регистрации должны совпадать. |
| UI-014 | Выход меняет header и закрывает доступ к истории; пароль не сохраняется. |
| UI-015 | История содержит запросы текущей сессии после входа и позволяет вернуться к результатам. |
| UI-016 | Каталог содержит семь demo-документов; поиск, статус и тип применяются совместно. |
| UI-017 | Карточка и drawer показывают номер, тип, орган, статус, даты и фрагмент. |
| UI-018 | Связанные документы открываются в том же drawer, кнопка Назад восстанавливает предыдущий документ. |
| UI-019 | Выбор и drop файла показывают метаданные; анализ имитируется, содержимое не читается. |
| UI-020 | OCR-flow имеет ожидание, успех, ошибку по имени error и повторную загрузку. |
| UI-021 | Навигация доступна на 1440, 1024 и 390 px; Escape закрывает modal и drawer, интерактивные элементы доступны с клавиатуры. |

Настоящие поиск по корпусу, ранжирование, авторизация и формирование ответа относятся к будущей реализации.
