# 02. Пользователи и сценарии

## Основной пользователь

Основной пользователь системы — сотрудник банка, финтех-компании или другой специалист, который в своей работе обращается к нормативным и справочным документам финансовой сферы.

Пользователь понимает предметную область и может сформулировать интересующий его вопрос, но не обязан знать:

- точное название нормативного документа;
- номер документа;
- раздел, в котором содержится нужная информация;
- точную формулировку, используемую в документе.

## Потребность пользователя

В процессе работы пользователю необходимо быстро найти нормативную информацию по конкретному вопросу.

Вместо самостоятельного просмотра большого количества документов пользователь формулирует вопрос в привычной форме и получает материалы, наиболее соответствующие его запросу.

Пример ситуации:

Сотруднику банка необходимо выяснить, в каких случаях банк может отказать клиенту в проведении операции. Пользователь не знает, в каком именно нормативном документе содержится соответствующее требование, поэтому выполняет поиск по смыслу вопроса.

## Основной пользовательский сценарий

### SC-01. Поиск нормативной информации

**Цель пользователя:** найти информацию по интересующему вопросу и определить нормативный источник.

**Предусловие:** система запущена, корпус документов доступен для поиска.

**Основной поток:**

1. Пользователь открывает приложение.
2. На главной странице пользователь видит поле для поискового запроса.
3. Пользователь вводит вопрос на естественном языке.
4. Пользователь запускает поиск.
5. Система обрабатывает запрос и выполняет поиск по корпусу документов.
6. Система отображает найденные результаты в порядке релевантности.
7. Для каждого результата пользователь видит:
   - название документа или источника;
   - релевантный фрагмент текста;
   - информацию об источнике.
8. Пользователь просматривает результаты и выбирает наиболее подходящий.
9. Пользователь может перейти к более подробной информации о найденном источнике.
10. В итоговой версии продукта пользователь также получает краткий ответ, сформированный на основе найденных материалов.

**Результат:** пользователь получает нормативную информацию по своему вопросу и может определить её источник.

## Альтернативные сценарии

### SC-02. Пустой запрос

1. Пользователь открывает приложение.
2. Не вводит текст в поисковое поле.
3. Пытается запустить поиск.
4. Система не выполняет поиск и сообщает пользователю, что необходимо ввести запрос.

### SC-03. По запросу ничего не найдено

1. Пользователь вводит поисковый запрос.
2. Система выполняет поиск.
3. Подходящие документы не найдены.
4. Система сообщает об отсутствии результатов.
5. Пользователь может изменить формулировку запроса и выполнить поиск повторно.

### SC-04. Просмотр источника

1. Пользователь получает результаты поиска.
2. Выбирает интересующий результат.
3. Открывает информацию об источнике.
4. Пользователь видит данные, позволяющие определить исходный документ.

## Типичный путь пользователя

Открытие приложения
→ ввод вопроса
→ запуск поиска
→ просмотр результатов
→ выбор подходящего результата
→ просмотр источника
→ получение необходимой информации.

## Ключевой принцип взаимодействия

Пользователь должен иметь возможность выполнять поиск без знания точного названия нормативного документа.

Основное взаимодействие строится вокруг вопроса пользователя на естественном языке и последующего просмотра релевантных материалов.
