# 05. Правила и значения данных

## Назначение документа

Документ определяет основные понятия, используемые в продукте, и правила работы с данными.

---

## 1. Основные понятия

### Пользовательский запрос

Пользовательский запрос — текстовый вопрос, который пользователь вводит в поисковое поле.

Запрос может быть сформулирован на естественном языке. Пользователь не обязан использовать точное название или формулировку нормативного документа.

Пример:

> В каких случаях банк может отказать клиенту в проведении операции?

---

### Корпус документов

Корпус — совокупность документов, по которым система выполняет поиск.

В рамках продукта используется заранее подготовленный корпус нормативных и справочных материалов финансовой сферы.

Пользователь не изменяет состав корпуса через интерфейс.

---

### Документ

Документ — отдельная единица текста, участвующая в поиске.

Документом может являться как целый исходный материал, так и его отдельный содержательный фрагмент.

Конкретный способ разделения исходных материалов на документы определяется при подготовке корпуса.

---

### Источник

Источник — исходный нормативный или справочный материал, из которого получен найденный документ или фрагмент.

Информация об источнике должна позволять пользователю определить происхождение найденного материала.

В зависимости от доступных данных она может содержать:

- название документа;
- организацию или орган, выпустивший документ;
- реквизиты документа;
- ссылку на исходный материал.

---

### Результат поиска

Результат поиска — документ или его фрагмент, который система определила как соответствующий запросу пользователя.

Для каждого результата пользователю отображаются:

- название;
- релевантный фрагмент текста;
- информация об источнике.

---

### Релевантность

Релевантность показывает степень соответствия найденного материала запросу пользователя.

Результаты поиска отображаются от наиболее релевантных к менее релевантным.

---

### Сформированный ответ

Сформированный ответ — краткий ответ на вопрос пользователя, построенный на основе материалов, найденных в корпусе.

Ответ не является самостоятельным источником информации. Пользователь должен иметь возможность определить документы, на основании которых он был сформирован.

---

## 2. Правила работы продукта

### RULE-001. Поиск выполняется только по корпусу

Система выполняет поиск только среди документов, содержащихся в используемом корпусе.

---

### RULE-002. Источник должен быть определим

Каждый результат поиска должен быть связан с исходным материалом таким образом, чтобы пользователь мог определить его источник.

---

### RULE-003. Результаты упорядочиваются по релевантности

При успешном поиске наиболее релевантные запросу материалы должны отображаться выше менее релевантных.

---

### RULE-004. Пустой запрос не обрабатывается

Если пользователь не ввёл текст запроса, поиск не выполняется.

---

### RULE-005. Отсутствие результатов отображается явно

Если подходящие материалы не найдены, система сообщает об этом пользователю и предоставляет возможность изменить запрос.

---

### RULE-006. Сформированный ответ основывается на найденных материалах

В итоговой версии продукта ответ пользователю должен формироваться на основе документов, найденных системой по его запросу.

---

### RULE-007. Ответ не скрывает источники

Сформированный системой ответ не должен заменять доступ к исходным материалам.

Пользователь должен иметь возможность обратиться к документам, на которых основан ответ.

---

### RULE-008. Система не принимает решения за пользователя

Результаты поиска и сформированный ответ носят информационный характер.

Система не принимает финансовые или юридические решения вместо специалиста.

---

### RULE-009. Пользователь не изменяет корпус

В текущей версии продукта пользователь не может добавлять, удалять или редактировать документы корпуса через пользовательский интерфейс.

---

## 3. Связь основных данных

Основной поток данных продукта:

Пользовательский запрос
→ поиск по корпусу
→ релевантные документы
→ информация об источниках
→ сформированный ответ на основе найденных материалов.

Один запрос может иметь несколько релевантных результатов.

Один исходный источник может содержать несколько документов или фрагментов, участвующих в поиске.

Каждый найденный материал должен сохранять связь со своим исходным источником.
